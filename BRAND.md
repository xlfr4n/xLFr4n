## 03 — UI rules

- Prefer **real information** over decorative metrics.
- Keep important states explicit: PUBLIC REPOSITORY, EXPERIMENT, VERIFIED.
- Use red for signal, not for every element.
- Keep borders subtle and hierarchy strong.
- Make mobile layouts first-class.
- Preserve visible keyboard focus.
- Respect prefers-reduced-motion.
- Avoid unnecessary dependencies for static experiments.
- Never present a claim as verified if it has not been checked.

---

## 04 — Writing rules

### Do

Use language such as:

- verified
- tested
- reproducible
- manually maintained
- public repository
- technical playground

### Avoid

Claims such as:

- invented usage numbers
- invented uptime
- fabricated performance figures
- vague “AI-powered” filler without a concrete feature
- status labels that imply monitoring when there is none

## 06 — Repository policy

The GitHub profile should remain the **entry point**, while individual repositories keep their own technical detail.

When a project is linked from the profile:

1. The repository should be public or intentionally described as unavailable.
2. The description should match what the repository actually contains.
3. Links should point to real paths.
4. Visual polish should never replace documentation.
5. CI should verify what can reasonably be verified automatically.
