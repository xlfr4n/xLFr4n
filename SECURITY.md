# 🔐 Security — xLFr4n // LAB

> **xLFr4n security standard · ES + EN**

## 🇪🇸

La seguridad y la preservación de datos tienen prioridad sobre la estética o la velocidad.

### Reportar un problema

No publiques en un Issue o Pull Request detalles explotables, credenciales ni material sensible.

Para comunicar un problema de seguridad, utiliza una vía privada de GitHub para **xLFr4n** y aporta, cuando sea posible:

- descripción técnica del problema;
- pasos mínimos para reproducirlo de forma segura;
- impacto observable;
- versión, commit o entorno afectado;
- evidencias que no contengan secretos.

No realices pruebas destructivas contra servicios de terceros ni contra infraestructura ajena.

### Reglas de datos

Nunca subas:
- private keys, seed phrases o tokens;
- cookies o sesiones reales;
- credenciales;
- información personal innecesaria;
- dumps sensibles.

### Nota forense

Cuando un repositorio contenga evidencia, hashes o artefactos de análisis, la **integridad y trazabilidad** tienen prioridad. No alteres evidencia primaria para facilitar una prueba.

## 🇬🇧

Security and data preservation take priority over aesthetics or speed.

Do not publish exploitable details, credentials or sensitive material in public Issues or Pull Requests. Use a private GitHub channel to contact **xLFr4n** and include the smallest safe reproduction, observable impact, affected version/commit and sanitized evidence.

Never upload private keys, seed phrases, tokens, cookies, sessions, credentials or unnecessary personal data.

For repositories containing evidence, hashes or analysis artifacts, preserve primary evidence and provenance.

**⚡ xLFr4n · Evidence first · Build responsibly**
